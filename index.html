OUR DEPLOYMENT · Architecture

Seven containers, one review pipeline

Orchestrated with Docker Compose on a single VM.

ContainerRolePort
kodus-webDashboard & configuration UI3000

kodus-webhooksReceives Git events3332

KEY DETAIL

Containers talk to each other by service name, e.g. api, not the VM's public IP. Only external calls (browser, GitLab webhooks) use it. Mixing up the two caused our first blocker.

OUR DEPLOYMENT · Troubleshooting

Five blockers, five fixes

Documented as we hit them, so the next deploy is faster.

01 · SIGNUP BLOCKED
Sign-up page unresponsive

Cause: WEB_HOSTNAME_API pointed at the public IP instead of the internal service name.

Set it to api, recreate kodus-web.

02 · MISSING QUEUE
RabbitMQ queue not found

Cause: the worker hadn't created its queues yet, services started in the wrong order.

Sequential restart: RabbitMQ → Worker → API/Web/Webhooks.

03 · CONTAINERS MISSING
kodus-web & webhooks not started

Cause: the install script doesn't always launch every service.

docker compose up -d kodus-web webhooks

04 · LLM TIMEOUT
Provider unreachable (15s timeout)

Cause: wrong LLM provider base URL or an invalid API key.

Verify & correct the exact endpoint URL.

05 · QUOTA HIT
LLM credits exhausted

Cause: free-tier limit reached mid-testing.

Rotate providers, Groq, Gemini, Mistral, Cerebras, OpenRouter.

OUR DEPLOYMENT · Limitations

What to plan around

Free-tier LLM quotas

Rate and credit limits on free providers can interrupt an analysis mid-run.

OpenRouter credit error

One attempt needed 65k tokens against a 35k limit, fell back to Groq.

Startup order matters

The worker must be up before the API for RabbitMQ queues to form correctly.

No domain / HTTPS yet

Current setup uses the VM's public IP directly, production needs a reverse proxy + TLS.

OUR DEPLOYMENT · Recommendations

Our take, for the team

What works well

Real, actionable detections, security, error handling and validation issues surface directly on the MR.

Easy to adopt, @kody review and 👍/👎 feedback need no training.

BYOK keeps full control over LLM cost and provider choice.

Before scaling up

Match the LLM provider's quota to real MR volume, free tiers suit testing, not daily heavy use.

Document the startup order internally for any redeploy.

Add a domain + reverse proxy (HTTPS) before use beyond internal testing.

Self-hosted Kodus with a free LLM provider (Groq) is a functional, zero-cost setup for a test phase or moderate-volume use. Moving to a paid provider is recommended before rolling it out to every Hackership Merge Request.
